# v21bot — бот стратегии v2.1 на Rust

Спецификация — [`docs/superpowers/specs/2026-10-18-v21bot-design.md`](../docs/superpowers/specs/2026-10-18-v21bot-design.md).
Планы вех — [первой](../docs/superpowers/plans/2026-10-18-v21bot-m1-core-replay.md) и
[второй](../docs/superpowers/plans/2026-10-19-v21bot-m2-live-demo.md).

**Веха 1 готова:** ядро стратегии и прогон по архиву. Прогон повторяет Python-бэктест (`ruslan_v2.py` +
`ruslan_v2_1.py`) сигнал в сигнал и сделка в сделку.

**Веха 2 готова:** живые ленты, два решения на каждый сигнал и демо-счёт. Бот ордеров не ставит. Боевой режим —
веха 3, запуск на реальные деньги — веха 4.

## Из чего состоит

| Крейт | Что внутри |
|---|---|
| `crates/core` (`v21-core`) | Вся логика v2.1 без сети, часов и файлов: параметры из замороженных JSON с проверкой sha256, детектор сигнала, цены Binance и z, номер монеты и решение, доходность и статистика |
| `crates/replay` (`v21-replay`) | Чтение parquet-архива, прогон через ядро, сравнение с таблицами Python, отчёт и CSV |
| `crates/live` (`v21-live`) | Живой бот: две копии ленты Polymarket и Binance, быстрый движок горячего потока, точный движок, демо-счёт, журнал и таблицы, Telegram, отчёт, сверка с архивом, проверка связи |
| `crates/cli` (`v21-cli`) | Исполняемый файл `v21` |

## Установка

Нужен Rust не ниже 1.88 (проверено на 1.99.1):

```powershell
rustup update stable
```

Для замера покрытия ещё:

```powershell
rustup component add llvm-tools-preview
cargo install cargo-llvm-cov --locked
```

## Тесты

Все команды — из папки `v21bot`.

Без архива (тесты, которым нужен архив, пишут `skipped: V21_ROOT is not set` и проходят):

```powershell
cargo test --workspace
```

С архивом: `V21_ROOT` — папка `15mbacktest`, где лежат `strategy_v2.json`, `strategy_v2_1.json`, `data/` и
`data_pre/`. Полная приёмка идёт в сборке release, иначе она долгая:

```powershell
$env:V21_ROOT="C:\Users\filip\Documents\15mbacktest"; cargo test --workspace
$env:V21_ROOT="C:\Users\filip\Documents\15mbacktest"; cargo test --release -p v21-replay --test acceptance -- --nocapture
```

Перед приёмкой таблицы Python должны быть свежими: после `forward.update()` запусти `python ruslan_v2.py`. Если
архив новее таблиц, сигналы новых окон печатаются отдельным списком «newer than the reference» и расхождением не
считаются.

Граница «новее» — последнее окно, в котором у таблицы Python есть сигнал. Сигнал прогона из окна позже него —
новый, из окна не позже него — расхождение. Списки расхождений и новых сигналов печатаются не длиннее 40 строк,
остальное — числом.

## Прогон по архиву

```powershell
cargo run --release -p v21-cli -- replay --root C:\Users\filip\Documents\15mbacktest
cargo run --release -p v21-cli -- replay --root C:\Users\filip\Documents\15mbacktest --period pre
```

- `--period main` (по умолчанию) — архив с 18.08 (`data/`), `--period pre` — 07–18.08 (`data_pre/`).
- `--out DIR` — куда писать таблицы (по умолчанию `replay_out`): `signals.csv` — все сигналы базового правила,
  `trades_v2.csv` и `trades_v21.csv` — сделки.
- Без `--root` берётся переменная `V21_ROOT`. Имена из спецификации тоже работают: `--data` и `V21_DATA`.
- Таблицу Python команда читает до прогона: если её нет, она сразу выходит с кодом 2 и называет файл.
- Закрытый вывод (`v21 replay | head`) — не ошибка: команда доделывает работу и пишет таблицы.

Команда печатает число окон и сигналов, вердикт сравнения с Python, строки расхождений (если есть) и таблицу
v2 / v2.1 / выкинутых сделок по периодам, как `ruslan_v2_1.py`.

**Коды выхода:**

| Код | Значит |
|---|---|
| 0 | прогон совпал с бэктестом |
| 1 | есть расхождения — они перечислены в выводе |
| 2 | плохой ввод: нет папки данных, нет или не читается файл, файлы стратегии не те, что заморожены |

## Демо-режим (веха 2)

Как ставить на сервер — [`deploy/README.md`](deploy/README.md). Коротко, что делает бот:

- **Ленты.** Две копии канала рынка Polymarket: каждое событие применяется один раз, из копии, что принесла его
  первой. Поток сделок Binance; если основной адрес отвечает 451 — зеркало. Время окна — по часам биржи: часы машины
  плюс поправка по NTP или по Binance.
- **Быстрое решение** — в горячем потоке, в момент попадания в коридор: номер монеты, быстрый z, правило v2.1,
  паузы, лимит выстрелов. Если всё выполнено — выстрел (в демо — демо-ордер). Горячий путь после прогрева не
  выделяет память.
- **Точное решение** — тем же ядром, что прогон по архиву, на тех же событиях, поставленных по времени биржи. День
  15.10 через точный движок даёт те же сигналы, номера и решения, что прогон вехи 1.
- **Демо-исполнение** — стакан купленного токена в момент исполнения (отправка + половина пути + задержка тейкера
  250 мс), $20 до комиссии, предел 0.88; цена без задержки и сетка 0–600 мс от отправки.
- **Демо-счёт** — $100, позиция на каждый исполненный выстрел, расчёт по официальному исходу; денег меньше ставки
  и резерва — пауза или стоп.
- **Файлы** — журнал `journal.jsonl`, состояние `state.json`, таблицы `trades.csv`, `signals.csv`, `windows.csv`;
  Telegram — входы, итоги, упущенные сделки, тревоги, сводка в 07:30 UTC.

**Команды:**

```powershell
v21 run --config v21bot.toml --secrets secrets.toml          # бот (Ctrl-C — остановка с сохранением)
v21 check --config v21bot.toml                               # можно ли работать: коды 0, 1, 2
v21 report --journal journal.jsonl --config v21bot.toml --from 2026-10-21 --to 2026-10-21
v21 reconcile --journal journal.jsonl --root C:\Users\filip\Documents\15mbacktest
```

**Дома, на ПК** — часы Windows могут уйти на секунду, поэтому предел поправки шире. Демо работает и дома, но
`v21 check` скажет «работать нельзя»: Polymarket закрыт для страны ПК (геоблок), а ордера нужны только с сервера.
Конфиг:

```toml
strategy_dir = "C:/Users/filip/Documents/15mbacktest"
[risk]
clock_max_offset_ms = 5000
[cores]
pin = false
[paths]
journal = "C:/v21/journal.jsonl"
state = "C:/v21/state.json"
stop_flag = "C:/v21/STOP"
```

Сквозные сценарии демо-режима — бот против поддельных серверов на часах биржи, сдвинутых на дни от часов машины.
Девять сценариев идут параллельно около 100 с:

```powershell
cargo test -p v21-live --test e2e -- --ignored
```

## Итоги приёмки (18.10.2026, данные до 18.10 17:59 UTC)

| Архив | Вердикт | Время |
|---|---|---|
| main | `signals 2748/2748 equal, z max diff < 1e-9, ranks equal, v2 trades 315/315, v2.1 trades 201/201` | 32.5 с |
| pre | `signals 517/517 equal, z max diff < 1e-9, ranks equal, v2 trades 69/69, v2.1 trades 55/55` | 1.7 с |

Таблица периодов `v21 replay` совпала с `ruslan_v2_1.side_by_side` во всех строках и колонках (до округления
печати). Например, v2.1 в форварде с 15.10: 10 сделок, 100% побед, +19.43% на сделку; за всё время с 18.08 —
201 сделка, 89.55%, +7.42% (t 2.86).

Расхождений с бэктестом не было. Финальное ревью нашло одно скрытое отличие: цены Decimal(9, 4) переводились в
double делением на 10⁴, а pyarrow умножает на `1e-4`. На ценах с 4-м знаком (0.8805) это разные биты, и
`np.round(x, 3)` округлил бы их по-разному. В нынешнем архиве таких цен нет, но перевод исправлен на умножение, как в
pyarrow (тест `decimal_cast_matches_pyarrow`), и приёмка основного архива после этого пройдена заново.

слишком долго). Сквозные сценарии демо помечены `#[ignore]` — второй замер идёт с ними (`--include-ignored`):

**Непокрытые строки и почему** — по второму замеру (`--show-missing-lines`). Ядро и прогон по архиву:

- **Пути только основного архива** — `replay/run.rs:174` (инциденты основного архива). Их проходят приёмка
  `main_archive_matches_python` и прогон `v21 replay` по основному архиву, которые запускаются отдельно от замера.
- **Вывод расхождений** — `compare.rs:66, 153, 168, 238-239`. Бывают только при расхождении с бэктестом, а его нет.
  Сама логика сравнения проверена тестом `each_kind_of_mismatch_is_one_problem_line`.
- **Схемы, которых нет в архиве** — `archive.rs`: время в секундах и наносекундах, `LargeBinary`, `Utf8View`,
  `asset_id` не бинарного типа, null во времени, бесконечная цена, плохой `INCIDENTS.json` (строки 72-73, 79-80,
  125-127, 133, 136, 138, 141, 144, 147, 178, 186, 190, 192, 201, 206-207, 212, 218, 293, 327); `compare.rs:87` —
  сторона не `Up` и не `Down` в таблице Python. Это защита на случай другого архива.
- **Случаи Python, недостижимые на замороженных файлах** — `pyjson.rs:16, 19, 68, 70-71, 92` (NaN, бесконечность,
  `\r`, `\b`, `\f`, целое больше i64), `window.rs:62-63, 72` (деление с остатком для отрицательных чисел),
  `window.rs:124, 129, 132` (разбор времени с неверными разделителями), `params.rs:112` (час не парой чисел).
- **Инварианты и защита** — `detector.rs:127`: проверка ждёт цену, которая после `reset()` всегда сброшена вместе с
  проверкой. `fill.rs:95`: уровень с нулевым размером — стаканы бота и архива отдают только уровни с размером.
  `live_closes.rs:187` — обрезка за последней известной секундой, `206` — секунда без цены и без пропуска при
  поиске назад: Binance для этого должен молчать минутами.
- **Пустые `is_empty`, `Default` и геттеры** — `closes.rs:68-70`, `live_closes.rs:54-56`, `archive.rs:97-99`,
